## Как сообщить об уязвимости

Сообщайте об уязвимостях **приватно**, а не через публичные issue.

- Используйте [приватные сообщения о уязвимостях](https://docs.github.com/code-security/security-advisories/guidance-on-reporting-and-writing/privately-reporting-a-security-vulnerability)
  в GitHub — кнопка «Report a vulnerability» на вкладке Security.
- Опишите, что вы сделали, что произошло и чего вы ожидали; лучше всего помогает
  минимальный пример воспроизведения.
- Первый ответ — примерно в течение недели. Проект ведёт один человек, наберитесь терпения.

Не прикладывайте к отчёту настоящие ключи, токены и личный видеоматериал. Если дело
касается ключа — сначала отзовите его, а в отчёте опишите ситуацию.

## Поддерживаемые версии

Поддерживается последняя версия в ветке `main`. Для старых версий исправления не выпускаются.

## Что программа делает с вашими данными

- **Без сервера с видеокартой** (`server.host` пуст) всё выполняется локально, кроме
  облачного перевода. Аудио и видео не покидают машину.
- В профиле `hybrid` на шлюз перевода уходит только **текст** распознанных реплик.
  В профиле `offline` без сервера с видеокартой после загрузки моделей наружу не уходит
  ничего.
- **С сервером с видеокартой** (`server.host` задан) стадии, включённые в `server.stages`,
  отправляют данные на эту машину по обычному, **незашифрованному HTTP**: звуковую дорожку
  (во FLAC) — для распознавания, диаризации и разделения; тексты реплик — для синтеза
  (`/v1/tts`) и голосов актёров (`/v1/clone`); для голосов актёров ещё и образец голоса
  каждого спикера, вырезанный из оригинала, вместе с его текстом
  (`PUT /v1/clone/ref/<sha256>`). Локальный перевод идёт в Ollama той же машины, так что
  туда уходят и тексты реплик; облачный перевод профиля `hybrid` остаётся на шлюзе.
  Пользуйтесь сервером только в сети, которой доверяете.
- **Ключи** (ключ шлюза перевода, токен Hugging Face) хранятся в `secrets.json` в каталоге
  кэша, а не в `config.yaml`. В веб-интерфейс ключ передаётся только в маскированном виде,
  никогда целиком, поэтому `config.yaml` можно спокойно пересылать. Схема настроек не
  принимает ключ там, где ожидается имя переменной: такой файл лечится, а значение
  переносится в хранилище ключей. С сервером с видеокартой токен Hugging Face уходит и на
  него — открытым текстом, в заголовке `X-HF-Token` каждого запроса диаризации, чтобы
  сервер мог скачать закрытые веса; сервис передаёт его процессу диаризации через
  переменную окружения и не сохраняет.
- **Локальный сервер** слушает только `127.0.0.1` на случайном порту, на каждый запуск
  выдаёт одноразовый токен, требует его для всех запросов `/api/*` и отказывается читать
  или отдавать пути вне рабочего каталога и каталога кэша.

## Сервис на сервере с видеокартой

`dubpipe-worker` (`python/dubpipe_worker.py`) рассчитан на машину в вашей собственной
сети, и модель безопасности у него намеренно простая:

- **Пароля нет.** Сервис слушает `0.0.0.0:8770` и отвечает только клиентам с частным или
  loopback-адресом по меркам модуля Python `ipaddress`; остальным — 403. Адреса Tailscale
  по IPv4 (`100.64.0.0/10`) по этому определению не частные, поэтому им тоже отказ.
- **Не открывайте порт в интернет**, особенно в Docker: при опубликованном порте клиенты
  могут выглядеть так, будто приходят с частного адреса шлюза сети Docker, и тогда фильтр
  по адресу пропускает всех.
- **`POST /v1/free` может вызвать любой узел сети**: он выгружает модели простаивающего
  ComfyUI на этой машине, идущую генерацию не трогает. Задача тоже может попросить
  освободить видеопамять — тогда выгружаются простаивающий ComfyUI, а затем модели Ollama.
- **Хранение.** Файлы задач (присланный звук и результаты) лежат в `data/jobs` и
  удаляются, когда клиент их забрал, или фоновой уборкой через 3 часа. Образцы голосов
  **не** убираются: они остаются в `data/refs`, пока вы их не удалите, —
  `~/dubpipe-worker/data/refs` после скрипта установки, `/data/refs` на томе
  `dubpipe-data` в Docker.
- **Загрузки по ссылке** от клиента принимаются только с `https://huggingface.co/` и
  `https://models.silero.ai/`.
- **Ollama на сервере** должна слушать сеть (`OLLAMA_HOST=0.0.0.0`), иначе перевод до неё
  не дойдёт, а аутентификации у неё нет: пользоваться её моделями и управлять ими может
  любой в сети. Профиль `--profile ollama` в `docker/worker/compose.yaml` публикует порт
  11434 вообще без фильтра по адресу.

## Известные зоны риска

Это свойства самой задачи — они описаны, а не скрыты:

- Загружаемые компоненты (ffmpeg, модели, голоса) скачиваются по HTTPS с сайтов
  первоисточников и проверяются только по размеру, без проверки подписи. Если в вашей среде
  это важно, используйте собственные зеркала.
- Необязательная стадия диаризации при нажатии кнопки загрузки ставит `pyannote.audio`
  через pip в активное окружение Python. Если это нежелательно, используйте виртуальное
  окружение.
- `scripts/server/install-worker.sh`, если uv не установлен, ставит его, передавая
  `https://astral.sh/uv/install.sh` из интернета прямо в `sh`, и записывает службу systemd
  в `/etc/systemd/system` через sudo (`SKIP_SERVICE=1` этот шаг пропускает). Прочитайте
  скрипт, прежде чем запускать.
- Образ Docker сервиса (`docker/worker/Dockerfile`) не задаёт `USER`: внутри контейнера
  сервис работает от root.
- Сборка для Windows не подписана сертификатом, поэтому SmartScreen показывает
  предупреждение.
