# Как участвовать

[English](CONTRIBUTING.md) · **Русский**

Спасибо за интерес. Проект небольшой и с ясной формой, поэтому правил немного — они нужны,
чтобы форма сохранилась.

## Подготовка

```bash
npm install
npm run typecheck
npm test            # 263 теста; не нужны ни ffmpeg, ни сеть, ни ключи
```

Тесты намеренно не требуют ничего внешнего. Если правка заставляет тест просить ffmpeg,
сеть или ключ — значит, этому коду место не в тестах, а в проверочном скрипте в `scripts/`.

Запуск без сборки:

```bash
npx tsx src/cli.ts doctor --fetch   # сначала загрузить внешние компоненты
npx tsx src/cli.ts ui
```

## Как устроен код

```
src/core/       конвейер, рабочий каталог, кэш, остановка, журнал
src/stages/     s1…s7 и субтитры — по файлу на стадию
src/providers/  asr, llm, tts, vad, диаризация — по папке на вид
src/ui/         локальный API-сервер и веб-интерфейс (src/ui/public)
src/util/       ffmpeg, загрузки, запуск процессов, wav/srt
python/         необязательные сайдкары: разделение голоса и диаризация
scripts/        проверки, которым нужны настоящие медиа, окно или сеть
tests/          vitest, только офлайн
```

Стадия читает и пишет `segments.json` через `Workspace` и сообщает о ходе через `log`.
Если добавляете операцию уровня стадии — держитесь этого контракта: именно он бесплатно
даёт проекту кэш, полосы прогресса и остановку.

## Пул-реквесты

- **Одно изменение на пул-реквест.** Исправление и рефакторинг в одном диффе — это два
  разных обзора.
- **Тест, который падает без вашей правки.** Тесты живут рядом с правилами, которые они
  защищают; стиль — в `tests/subtitles.test.ts`: по тесту на правило, название человеческим
  языком.
- Перед отправкой прогоните `npm run typecheck` и `npm test`. TypeScript в строгом режиме.
- Комментарии объясняют **почему**, а не **что**. Пишите на языке того файла, который
  правите.
- Если меняется поведение, заметное пользователю, — обновите оба README (`README.md` —
  основной, `README.ru.md` — русская версия).
- Если меняете то, что измерялось (время, качество, пороги), — напишите, что и на каком
  материале вы измерили. Числа в этом проекте берутся из настоящих прогонов, а не из оценок.

## Сообщения об ошибках

Укажите версию, ОС, что запускали и что получилось. Полезнее всего приложить `run.log` из
рабочего каталога обработанного файла — там записан ход каждого прогона. Уберите из него
личное и никогда не прикладывайте ключи.

## Что не будет принято

- Любая возможность выгружать, публиковать или распространять полученную дорожку.
  Инструмент — для личного просмотра; это осознанная граница, а не недоработка.
- Включение чужих исполняемых файлов в репозиторий. Они загружаются во время работы, и это
  держит лицензии в порядке — см. [THIRD-PARTY-NOTICES.ru.md](THIRD-PARTY-NOTICES.ru.md).
- Эвристическая «псевдодиаризация» по признакам сигнала вместо настоящей модели: она даёт
  нестабильную привязку голосов между сценами.
