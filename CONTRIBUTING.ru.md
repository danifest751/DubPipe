# Как участвовать

[English](CONTRIBUTING.md) · **Русский**

Спасибо за интерес. Проект небольшой и с ясной формой, поэтому правил немного — они нужны,
чтобы форма сохранилась.

## Подготовка

```bash
npm install
npm run typecheck
npm test            # 284 теста; не нужны ни ffmpeg, ни сеть, ни ключи
```

Тесты намеренно не требуют ничего внешнего. Если правка заставляет тест просить ffmpeg,
сеть или ключ — значит, этому коду место не в тестах, а в проверочном скрипте в `scripts/`.

Запуск без сборки:

```bash
npx tsx src/cli.ts doctor --fetch   # сначала загрузить внешние компоненты
npx tsx src/cli.ts ui
```

## Как устроен код

```
src/core/       конвейер, рабочий каталог, кэш, остановка, журнал
src/stages/     s1…s7 и субтитры — по файлу на стадию
src/providers/  asr, llm, tts, vad, диаризация — по папке на вид
src/ui/         локальный API-сервер и веб-интерфейс (src/ui/public)
src/util/       ffmpeg, загрузки, запуск процессов, wav/srt
python/         необязательные сайдкары: разделение голоса и диаризация
scripts/        проверки, которым нужны настоящие медиа, окно или сеть
tests/          vitest, только офлайн
```

Стадия читает и пишет `segments.json` через `Workspace` и сообщает о ходе через `log`.
Если добавляете операцию уровня стадии — держитесь этого контракта: именно он бесплатно
даёт проекту кэш, полосы прогресса и остановку.

## Пул-реквесты

- **Одно изменение на пул-реквест.** Исправление и рефакторинг в одном диффе — это два
  разных обзора.
- **Тест, который падает без вашей правки.** Тесты живут рядом с правилами, которые они
  защищают; стиль — в `tests/subtitles.test.ts`: по тесту на правило, название человеческим
  языком.
- Перед отправкой прогоните `npm run typecheck` и `npm test`. TypeScript в строгом режиме.
- Комментарии объясняют **почему**, а не **что**. Пишите на языке того файла, который
  правите.
- Если меняется поведение, заметное пользователю, — обновите оба README (`README.md` —
  основной, `README.ru.md` — русская версия).
- Если меняете то, что измерялось (время, качество, пороги), — напишите, что и на каком
  материале вы измерили. Числа в этом проекте берутся из настоящих прогонов, а не из оценок.

## Сообщения коммитов

Коммиты оформляются по [Conventional Commits](https://www.conventionalcommits.org/):
тип, необязательная область и заголовок, говорящий, что делает изменение. Что изменилось
построчно — видно в диффе, поэтому тело сообщения говорит **почему**.

```
perf(asr): skip diarization when a run has no voicing stage

Speakers are only used to hand out voices on S5, so a subtitles run paid for
them with minutes of work it could not use: on a 12-minute episode diarization
took 4m27s of the 5m46s spent on recognition.

The effective configuration now drops diarization when S5 is not in the plan,
and the S2 fingerprint is computed from it, so a later dubbing run cannot reuse
a transcript that has no speakers in it.

Fixes #123
```

**Типы:**

| тип | когда |
|---|---|
| `feat` | новая возможность, доступная пользователю |
| `fix` | дефект в существующем поведении |
| `perf` | то же поведение, но измеримо быстрее или дешевле |
| `refactor` | только форма кода, поведение не меняется |
| `docs` | только документация |
| `test` | только тесты |
| `build` | зависимости, сборка, упаковка приложения |
| `ci` | рабочие процессы и автоматизация |
| `chore` | хозяйственные правки, не попавшие никуда выше |
| `revert` | отмена прежнего коммита |

**Области** называют часть конвейера или программы: `asr`, `translate`, `tts`, `align`,
`mix`, `subtitles`, `diarization`, `ui`, `cli`, `config`, `core`, `scripts`. Если правка
охватывает слишком многое, область опускается.

Правила:

- **Заголовок:** до 72 символов вместе с типом, повелительное наклонение (`add`, `fix`,
  `skip`, а не `added` и не `adds`), со строчной буквы после двоеточия, без точки в конце.
  Он завершает фразу «Applied, this commit will …».
- **Пустая строка** между заголовком и телом. Без неё инструменты считают всё сообщение
  одним абзацем.
- **Тело:** причина, найденный дефект, принятое решение и то, что вы отвергли.
  Переносы — около 72 символов. Тело можно опустить, только если заголовок правда
  говорит всё.
- **Числа, если поведение измерялось.** Меняете время, качество или пороги — приведите
  замер и материал, на котором он получен. Числа в этом проекте берутся из настоящих
  прогонов, и история — то место, где они хранятся.
- **Одно изменение — один коммит.** Исправление и рефакторинг — это два коммита.
- **Английский язык**, как код и основной README.
- **Трейлеры в конце**, после пустой строки: `Fixes #123`, `Co-Authored-By: Имя <почта>`.
  Ломающее изменение отмечается восклицательным знаком после типа (`feat(cli)!: …`) и
  объясняется в трейлере `BREAKING CHANGE:`.

Не пишите `chore: update files`, `fix: правки`, `wip` или просто список файлов — через год
такое сообщение стоит кому-то часа раскопок.

Чтобы подсказки появились в редакторе:

```bash
git config commit.template .gitmessage
```

## Сообщения об ошибках

Укажите версию, ОС, что запускали и что получилось. Полезнее всего приложить `run.log` из
рабочего каталога обработанного файла — там записан ход каждого прогона. Уберите из него
личное и никогда не прикладывайте ключи.

## Что не будет принято

- Любая возможность выгружать, публиковать или распространять полученную дорожку.
  Инструмент — для личного просмотра; это осознанная граница, а не недоработка.
- Включение чужих исполняемых файлов в репозиторий. Они загружаются во время работы, и это
  держит лицензии в порядке — см. [THIRD-PARTY-NOTICES.ru.md](THIRD-PARTY-NOTICES.ru.md).
- Эвристическая «псевдодиаризация» по признакам сигнала вместо настоящей модели: она даёт
  нестабильную привязку голосов между сценами.
