# DubPipe

[English](README.md) · **Русский**

Автоматический дубляж видео EN → RU: на вход видеофайл или YouTube-URL, на выход — тот же
видеоряд с русской озвучкой вместо английской речи, с сохранением музыки и эффектов.

> ## ⚠️ Только для личного просмотра
>
> DubPipe предназначен исключительно для частного копирования — просмотра дома.
> **Публикация или распространение полученной дорожки нарушает права правообладателя
> и правила платформ.** Инструмент намеренно не содержит и не будет содержать функций
> выгрузки результата куда-либо.

## Требования

- **Node.js 20+** (проверено на 25.9)
- ~2 ГБ свободного места под модели и бинарники
- GPU **не нужен**, но ускоряет: см. [«Видеокарта»](#видеокарта)
- Python нужен только для двух необязательных стадий: отделения голоса (S4,
  `pip install numpy onnxruntime`) и диаризации спикеров (S2, `pip install
  pyannote.audio` — тянет PyTorch, ~1 ГБ; интерфейс ставит его сам по кнопке
  «Догрузить недостающее»). Необязательный `pip install onnxruntime-directml`
  переносит отпечатки голосов на видеокарту и ускоряет диаризацию вчетверо. Без Python S4 откатывается на приглушение оригинала,
  а все реплики получают один голос; остальной конвейер Python не использует

Внешние компоненты (ffmpeg, yt-dlp, whisper.cpp, piper) DubPipe скачивает сам
в каталог `.dubpipe/tools` — **без установки в систему и без прав администратора**.
Если они уже есть в `PATH`, используются системные.

## Установка

```bash
npm install
npm run build          # либо работать через npx tsx src/cli.ts
npx tsx src/cli.ts doctor --fetch   # загрузить недостающие компоненты (~165 МБ)
```

## Графический интерфейс

```bash
npm run ui          # откроется в браузере
npm run app:dev     # то же самое в окне приложения
npm run app:build   # собрать .exe (установщик + портативная версия)
```

Интерфейс построен вокруг одного объекта — видеофайла. Главный экран — папка
с видео: у каждого файла видно, озвучен он или нет, и кнопка «Дублировать».
Страница файла — запуск, ход стадий, готовое видео, **редактор реплик**
с прослушиванием оригинала и синтеза, сравнение моделей и журнал.

Настройки — обычная форма по группам: перевод (облачная модель или локальная,
ключ доступа с проверкой, модель), голос с прослушиванием, распознавание,
звук с ползунками, подгонка, система. Каждое поле подписано; ошибочное значение
подсвечивается у поля. Для тех, кому удобнее файл, есть вкладка «Файл YAML».
Ключ доступа вводится в программе и хранится отдельно от настроек.

Если чего-то не хватает — программы, весов модели, голоса или ключа, — на главном
экране сверху появляется панель: что именно не выполнится и как это исправить.
Кнопка «Догрузить недостающее» закрывает всё разом: программы и веса качаются
параллельно, с полосами хода. Когда всё в порядке, панели нет.

Сервер слушает только `127.0.0.1` на случайном порту, каждый запуск выдаёт
одноразовый токен, пути из запросов не читаются вне рабочего каталога,
а ключ API в веб-приложение не передаётся — только факт его наличия.

Собранное приложение не требует ни Node.js, ни Python: `release/DubPipe Setup 1.0.0.exe`
(установщик) или `release/DubPipe-portable-1.0.0.exe` (без установки), по 229 МБ.
Рабочий каталог установленного приложения — `%APPDATA%/DubPipe`.

## Быстрый старт

```bash
# 1. Создать конфигурацию
npx tsx src/cli.ts config init

# 2. Проверить окружение
npx tsx src/cli.ts doctor

# 3. Получить дублированное видео
npx tsx src/cli.ts process video.mp4 --out video.ru.mp4

# 4. Посмотреть распознанное и переведённое
npx tsx src/cli.ts export-srt video.mp4 --lang ru
```

## Языки

**Язык оригинала** — параметр, а не допущение. Задайте `asr.language`, и конвейер
подстроит то, что действительно зависит от письменности: насколько перевод может
быть длиннее оригинала (английский ×2, корейский ×3, китайский и японский ×5 —
иероглиф несёт больше смысла, чем буква), склеиваются ли слова пробелами, ширину
строки субтитра, скорость чтения и знаки конца предложения. Для языка без профиля
действуют латинские правила. Файлы субтитров называются по коду языка: у корейского
эпизода получится `эпизод.ko.srt` рядом с `эпизод.ru.srt`.

**Язык интерфейса** переключается рядом с названием программы и запоминается между
запусками. Доступны русский и английский; текст, который приходит с сервера (например,
панель готовности), тоже переводится. Сообщения конвейера в журнале остаются русскими.

## Профили исполнения

| | Профиль `offline` | Профиль `hybrid` (по умолчанию) |
|---|---|---|
| Сеть после загрузки моделей | не нужна | нужна только для перевода |
| Ключи API | не нужны | нужен ключ Kilo для S3 |
| Перевод | локальная LLM через Ollama | `anthropic/claude-sonnet-4.5` |
| Всё остальное | локально | локально |

Переключение — одной строкой в `config.yaml`:

```yaml
profile: offline
```

Если в профиле `hybrid` ключ не задан или шлюз недоступен, перевод автоматически
деградирует до локального — конвейер не падает.

### Локальный перевод через Ollama

Профиль `offline` переводит локальной моделью: ничего не уходит в сеть, ключи не
нужны, каждая серия бесплатна. Что для этого нужно:

1. Поставить Ollama (`winget install Ollama.Ollama` или с ollama.com) и скачать
   модель: `ollama pull qwen2.5:7b-instruct`. Профиль `offline` берёт именно её,
   если вы не выбрали другую.
2. В интерфейсе: «Настройки → Перевод», профиль «офлайн» — в поле модели появится
   список того, что скачано локально. В `config.yaml` то же самое:

```yaml
profile: offline
translate:
  model: qwen3:8b            # имя как в `ollama list`
  ollama_endpoint: http://127.0.0.1:11434
```

Экран «Окружение» проверяет не факт установки Ollama, а то, отвечает ли демон и
скачана ли именно выбранная модель.

**Встроенную видеокарту нужно включить явно.** Ollama видит её и молча
отбрасывает — в журнале это выглядит как `dropping integrated GPU; to enable,
set OLLAMA_IGPU_ENABLE=1`. Выставьте эту переменную окружения и перезапустите
Ollama. Замер на Radeon 780M, настоящий запрос стадии перевода:

| | через Vulkan | только процессор |
|---|---|---|
| Разбор запроса | 243 ток/с | 59.6 ток/с |
| Генерация | 8.9–16.2 ток/с | 6.0 ток/с |

ROCm на этой карте не работает (`no rocblas support for gfx target gfx1103`), а
Vulkan работает через штатный драйвер AMD. Памяти видеокарте достаётся не только
BIOS-буфер: при общей памяти Ollama показала доступными 27.9 ГБ из 40, то есть
14B помещается свободно.

**Как они переводят.** Замер штатным `dub compare` на двадцати репликах реального
эпизода: сколько переводов уложилось в отведённое число знаков (ТЗ требует ≥90%).

| Модель | Уложилось | Запросов на 20 реплик | Время |
|---|---|---|---|
| `qwen3:4b` | 6/20 | 21 | 133 с |
| `qwen3:8b` | 7/20 | 13 | 227 с |
| `qwen3:14b` | 5/20 | 13 | 402 с |
| `mistral-nemo:12b` | 6/20 | 13 | 284 с |
| `qwen2.5:7b-instruct` | 6/20 | 13 | 300 с |

Размер модели здесь не решает: 14B оказалась худшей и втрое медленнее четвёрки.
Переводят все понятно, но **бюджет длины не соблюдает никто** — а от него зависит,
попадёт ли реплика в свой слот. Дальше это доберёт стадия S6, сокращая реплики
той же локальной моделью, то есть медленное умножается на себя. Выборка мелкая,
двадцать реплик, и на другом материале расклад может отличаться — но порядок
величины таков.

**Чего ожидать по времени.** Генерация упирается в пропускную способность
памяти, поэтому скорость обратно пропорциональна размеру модели: 7–8B в Q4 дают
около 9–16 токенов в секунду, 12–14B — вдвое меньше. Эпизод из 136 реплик — это
порядка 20 000 токенов запроса и 4 000 ответа, то есть **минуты, а не секунды**;
в облаке та же работа занимает минуту и стоит центы. Локальный перевод имеет
смысл ради офлайна и приватности, а не ради экономии.

### Финальная рецензия перевода

Перевод идёт пакетами по десять реплик и видит трёх соседей — этого хватает для фразы,
но не для фильма. Целый класс ошибок в такой рамке невидим: имя героини в трёх
написаниях, мужской род у женского персонажа, «ты» в одной сцене и «вы» в соседней,
кусок, оставшийся непереведённым. Рецензия — ещё один проход, который видит **весь
перевод разом**, вместе с полом каждого говорящего (замеренным по голосу на S2),
именами персонажей и глоссарием.

```yaml
translate:
  review:
    enabled: true   # профиль hybrid включает её сам; false — отказаться
```

**Решает профиль.** В `hybrid` рецензия идёт по умолчанию: облачной модели этот проход
окупается — на нарочно испорченном эпизоде `claude-sonnet-4.5` предложил 13 правок, и все
13 прошли предохранители, за 18 с. В `offline` она выключена: тот же прогон дал
`mistral-nemo:12b` 133 с на одну-единственную правку, и та оказалась выдумкой. Написанное
в `config.yaml` сильнее профиля.

Правки принимаются не на веру. Каждая проходит ту же мерку укладки, которой пользуются
перевод и подгонка: правка, ухудшающая попадание в слот, отклоняется — иначе мы меняем
точность на рассинхрон. А рецензия, переписавшая больше половины реплик, отбрасывается
целиком: это уже не правка, а новый перевод.

Правка, не уложившаяся в слот, не выбрасывается молча: рецензии показывают её же
предложение, её же причину и точную нехватку знаков и просят уложиться, сохранив
исправление (`fit_retries`).

Замер на настоящем эпизоде — 136 реплик, перевод намеренно испорчен слабой моделью,
рецензент `anthropic/claude-sonnet-4.5`, 18 секунд:

| | |
|---|---|
| Предложено правок | 13 |
| **Принято** | **13** |
| Из них добрано переспросом | 4 |

Среди них: «ты действительно **начал** вести себя странным — что случилось с **Эвей**» →
«**начала** вести себя странно — что случилось с **Евой**» (род, грамматика и падеж имени
в одной строке), «Я бы **хотел** их узнать» → «хотела», «ты, наверно, **прав**» →
«**права**» — здесь род собеседника, выведенный из соседних реплик, — и шесть строк,
оставшихся непереведёнными.

**Мерка — цель, а не потолок.** Первая версия говорила модели «не длиннее N знаков», и та
послушно возвращала вдвое короче: из 46 предложенных правок 27 отсеивались, потому что
недолёт по мерке конвейера — такой же промах, как перелёт (реплика отзвучит и оставит
паузу). После замены потолка на цель с границами допуска модель и предлагает вчетверо
меньше лишнего, и попадает почти всегда.

**Рецензия правит и субтитры.** Русские субтитры собираются из того же `segments.json`,
что и озвучка, поэтому исправленный текст попадает в них сам собой.

**Рецензента выбирайте сильного.** Предохранители стерегут тайминг, а не смысл:
уложившаяся в слот выдумка пройдёт насквозь, и дешёвой машинной проверки тут нет —
чтобы понять, что правка не о том, надо понимать текст. Замер на одном и том же
материале:

| | `claude-sonnet-4.5` | `mistral-nemo:12b` | `qwen3:14b` |
|---|---|---|---|
| Предложено правок | **13** | 1 | 5 |
| Принято | **13** | 1 | **0** |
| Пустышек (текст не изменён) | 0 | 0 | 4 |
| Время | **18 с** | 133 с | 196 с |

Единственная правка `mistral-nemo` оказалась выдумкой: строку «Hey, I care about Ethan
just as much as you do get a grip» она заменила на «Ну да, я был не в себе, но я не могу
просто так взять и уйти» — и это прошло проверку длины. `qwen3:14b` вернула четыре
пустышки и не изменила ничего.

Поэтому рецензию имеет смысл заказывать облачной модели, даже если перевод идёт локально:
`review.model` задаётся отдельно от `translate.model`. Это один проход на фильм — дешевле
самого перевода.

Тонкая настройка — в `config.yaml`: какие проверки включены (`checks`), порог отбрасывания
(`max_changes_share`), размер захода для очень длинных фильмов (`batch_lines`).

### Ключ Kilo Gateway

```bash
# Linux/macOS
export KILO_API_KEY="ваш-токен"
# Windows PowerShell
$env:KILO_API_KEY = "ваш-токен"
```

Имя переменной меняется полем `kilo_gateway.api_key_env`.

**Важно о возможностях шлюза** (проверено эмпирически, см. ТЗ §3.1.1): Kilo Gateway
маршрутизирует только `/chat/completions`. Синтеза речи у него нет ни в каком виде,
а транскрипция не возвращает таймкоды. Поэтому ключ используется **только для перевода**,
а распознавание и синтез всегда выполняются локально.

## Команды

| Команда | Назначение |
|---|---|
| `dub process INPUT [--out FILE] [--out-dir DIR] [--subtitles] [--model ID] [--from-stage ID] [--to-stage ID]` | обработать вход |
| `dub config init [--force]` | создать `config.yaml` из примера |
| `dub cache clear [INPUT]` | очистить кэш стадий |
| `dub doctor [--fetch]` | проверить и доустановить зависимости |
| `dub models [--search TEXT] [--free]` | список моделей перевода с ценами |
| `dub compare INPUT --models A,B [--apply M]` | сравнить качество перевода на нескольких моделях |
| `dub ui [--port N] [--no-open]` | графический интерфейс |
| `dub voices list` | голоса активного TTS-движка |
| `dub export-srt INPUT [--lang en\|ru]` | выгрузить субтитры |
| `dub evaluate INPUT [--golden FILE]` | сверить таймкоды с эталоном |

Коды возврата: `0` — успех, `1` — ошибка стадии, `2` — ошибка конфигурации,
`3` — отсутствует внешняя зависимость.

### Выбор и сравнение моделей перевода

Модель задаётся полем `translate.model`, разово — флагом `--model`:

```bash
npx tsx src/cli.ts models --search claude        # что вообще доступно и почём
npx tsx src/cli.ts models --free                 # только бесплатные
npx tsx src/cli.ts process video.mp4 --model anthropic/claude-opus-5
```

Чтобы выбрать модель не на слух, а по данным, — прогоните одни и те же реплики
через несколько моделей и сравните:

```bash
npx tsx src/cli.ts compare video.mp4   --models anthropic/claude-sonnet-4.5,openai/gpt-5.2,google/gemini-3.8-flash
```

Вывод — сводка и построчное сравнение:

```
модель                       в допуске    время     токены     стоимость
────────────────────────────────────────────────────────────────────────
anthropic/claude-sonnet-4.5  5/5 (100%)   4.8 с     1654       $0.00798
openai/gpt-5.2               5/5 (100%)   3.8 с     1827       $0.00527
google/gemini-3.8-flash      5/5 (100%)   11.4 с    2946       $0.00745

[3] слот 0.66 с — Fair enough.
    ✓ anthropic/claude-sonnet-4.5        Справедливо.
    ✓ openai/gpt-5.2                     Сойдёт.
    ✓ google/gemini-3.8-flash            И то верно.
```

Понравившийся вариант применяется к `segments.json` без повторного перевода:

```bash
npx tsx src/cli.ts compare video.mp4 --models A,B --apply A
```

Полезные флаги: `--limit N` — взять только первые N реплик (дешевле), `--timeout N` —
лимит секунд на модель, чтобы одна зависшая не тормозила остальные. Локальные модели
участвуют в сравнении с префиксом `ollama:`, например `ollama:qwen2.5:7b-instruct`.

### Возобновление и ручная правка

Все стадии кэшируются по содержимому входа и настройкам стадии, поэтому повторный
запуск ничего не пересчитывает. Ключ кэша включает отпечаток предыдущей стадии:
изменили настройки распознавания — перевод и синтез пересчитаются автоматически.

Между стадиями `segments.json` можно править руками (файл лежит в рабочем каталоге,
путь печатается в конце запуска), а затем продолжить с нужного места:

```bash
npx tsx src/cli.ts process video.mp4 --from-stage s3
```

Там же лежит `run.log` — журнал всех прогонов этого файла (каждый запуск
дописывает новый блок). Если результат выглядит странно, в первую очередь
смотреть туда и в `segments.json`.

Прогон можно оборвать в любой момент: кнопка «Остановить» в интерфейсе или
Ctrl+C в консоли (код возврата 130). Дочерние процессы убиваются сразу,
запросы к модели обрываются; готовые стадии остаются в кэше, а прерванная
пересчитается при следующем запуске.

## Субтитры

Кроме дубляжа программа делает субтитры: кнопка **«Субтитры»** у файла (или
`--subtitles` в консоли) проходит распознавание и перевод и кладёт рядом с видео
два файла — `<имя>.en.srt` и `<имя>.ru.srt`.

```bash
npx tsx src/cli.ts process video.mp4 --to-stage s3 --subtitles
```

### Что делается с оригинальной дорожкой

Русская речь ложится поверх оригинала, и с ним надо что-то делать. Способа три,
и выбирается он сам по настройкам.

Без разделения (по умолчанию) оригинал **приглушается** на 18 дБ под нашей
речью. Просто и надёжно, но вместе с чужим голосом приседает и музыка.

При включённом разделении из оригинала **вычитается выделенный голос** — и
только там, где звучит наша речь. Музыка остаётся в полной громкости, а между
репликами оригинал не тронут вовсе: песня, которую мы не дублируем, сохраняет
вокал. Это поведение по умолчанию, `separation.apply: under_speech`.

Вариант `everywhere` заменяет оригинал пересобранным фоном на весь фильм.
Убирает исходный голос везде, но и песни лишает вокала.

### Темп речи измеряется, а не угадывается

От того, сколько знаков синтезатор выговаривает за секунду, зависит, какой длины
заказывать перевод. Одним числом это не описать: у каждой реплики есть постоянная
надбавка — подход к фразе и хвост после неё. Замер на 255 репликах одного голоса:
реплики короче 15 знаков идут со скоростью 10.2 знака в секунду, длиннее 80 — со
скоростью 16.6, хотя голос один и тот же.

Поэтому подгоняется прямая `длительность = надбавка + знаки / темп`; на том же
материале вышло 0.51 секунды и 17.8 знака в секунду. Настоящий темп речи, как
видно, почти вдвое выше кажущегося, и раньше у длинных реплик просили на треть
меньше текста, чем в них влезает.

Оба числа измеряются на каждом прогоне и запоминаются — и для этой записи, и для
голоса вообще, чтобы первый же прогон следующего видео целился правильно. Замер
чужого голоса не используется: он хуже честного умолчания.

### Укладка по времени

Реплика, не влезающая в свой слот, раньше переписывалась короче через модель —
и теряла смысл. Теперь укладка сначала занимает тишину после реплики, до
полутора секунд, не залезая на следующую. На корейском эпизоде это снизило
число переписанных реплик с 52 до 1, а ускоренных — со 114 до 9.

Титры строятся не «как есть из реплик», а по правилам читаемости: не более двух
строк по 42 символа, длительность 1–7 с, зазор между титрами, скорость чтения до
17 знаков в секунду; длинная реплика делится по предложениям. Правила меняются
в настройках (`subtitles:` в `config.yaml`).

Вкладка **«Субтитры»** на странице файла показывает титры обоих языков, замечания
по каждому (быстро читать, наложение, длинная строка), позволяет править текст и
таймкоды и показывает их поверх видео. Правки сохраняются в SRT кнопкой
«Сохранить SRT»; «Пересобрать из реплик» возвращает расчётный вариант.

Прогон без озвучки — субтитры или всё, что заканчивается переводом, — пропускает
диаризацию: спикеры нужны только для раздачи голосов. На 15-минутном эпизоде
распознавание занимает около 1.5 минут вместо пяти-шести с диаризацией. Кэш
распознавания различает эти два случая, поэтому дубляж не возьмёт из кэша
распознавание без спикеров.

## Видеокарта

Два самых долгих расчёта умеют считаться на видеокарте, и это разные механизмы.

**Распознавание речи.** Официальный проект whisper.cpp не выпускает сборок под
AMD, поэтому автоматически берётся процессорная. Сборку с Vulkan можно включить
вручную — `asr.backend: vulkan`, — и программа скажет, что архив собран третьей
стороной. На Radeon 780M распознавание эпизода ускорилось вдвое: 2 мин 18 с
против 4 мин 57 с. Текст при этом расходится примерно на 9%: у бэкендов разное
округление, и на трудных местах — крик, песня — пути декодирования расходятся.

**Разбор, кто говорит.** Здесь 96% времени занимает одна сеть — голосовых
отпечатков, 105 секунд из 108 на пятиминутном отрезке. Она выгружается в формат
ONNX и считается через DirectML на любой видеокарте с DirectX: 27 секунд против
122 на процессоре, вчетверо быстрее, результат совпадает до пятидесяти
миллисекунд и до ярлыка говорящего. Сеть сегментации при этом остаётся на
процессоре: она крошечная, и на видеокарте была бы вдесятеро медленнее —
пересылки съедают больше, чем экономят вычисления.

**Отделение голоса от музыки.** Та же картина: тяжёлая сеть плюс лёгкая
обработка сигнала. Сеть переехала на видеокарту, преобразование Фурье осталось
в numpy. Минута звука обрабатывается за 3 секунды вместо 17 — впятеро быстрее, а
результат совпадает с процессорным до −94 дБ, то есть ниже порога слышимости.

Ничего настраивать не нужно: если установлен `onnxruntime-directml`, отпечатки
считаются на видеокарте, иначе — прежним путём. Выгрузка в ONNX делается один
раз и остаётся рядом с весами.

Устройство выбирается для каждой стадии отдельно — настройками
`asr.diarization.device` и `separation.device` с одинаковым словарём: `auto`,
`cpu`, `gpu`, `igpu`, `dgpu`. Одной галочки «всё на видеокарту» нет намеренно:
сеть сегментации на ней вдесятеро медленнее, чем на процессоре.

Разбор по голосам к тому же не пересчитывается зря. Он зависит только от звука и
своих настроек, а не от того, какой моделью распознан текст, — поэтому результат
хранится с отпечатком записи и переиспользуется. Смена модели распознавания
раньше стоила все семнадцать минут заново, теперь — ноль.

Что и где считается, показывает `dub doctor`: найденные видеоадаптеры, стадия
за стадией — на чём каждая работает, и чего не хватает, чтобы ускорить.

ROCm под Windows для этого не нужен и не рекомендуется: MIOpen собирает ядра во
время работы, а в пакетах ROCm нет стандартных заголовков C++, и сборка падает
на любом ядре. Это дефект самой AMD, воспроизводимый и на поддерживаемых
видеокартах ([ROCm#6150](https://github.com/ROCm/ROCm/issues/6150)).

## Выдумки распознавания

Whisper учили в том числе на файлах субтитров, поэтому на музыке и в тишине он
выписывает служебные строки оттуда: кто сделал субтитры, предупреждение о рекламе,
«спасибо за просмотр», призыв подписаться. Иногда он залипает и повторяет одну
фразу минутами. На корейском эпизоде так набралось 68 реплик из 412 — каждая
шестая: конвейер честно перевёл их и озвучил.

Стадия S2 их убирает. Известные формулы титров отсеиваются по списку, а залипание
распознаётся по свойству, которого у настоящей речи не бывает: одинаковые реплики,
наложенные друг на друга по времени. Повторы без наложения остаются — персонаж
действительно может двенадцать раз подряд сказать «серьёзно?».

Если реплики уже распознаны и вычищать нужно готовый рабочий каталог, есть скрипт:

```bash
npx tsx scripts/clean-hallucinations.mts "<путь к видео>"          # только показать
npx tsx scripts/clean-hallucinations.mts "<путь к видео>" --apply  # записать
```

Перед записью он сохраняет `segments.json.before-clean`.

## Сколько места это занимает

Конвейер обменивается несжатым звуком, и рабочий каталог растёт быстро. После сведения
черновые дорожки удаляются сами — на 15-минутном эпизоде это 585 МБ, — но входы стадий
остаются, чтобы повторный прогон не считал всё заново. Порядок величин: 15-минутный эпизод
занимает около 660 МБ, плюс общие модели (whisper, pyannote, MDX, голоса) — около 5 ГБ на
всех.

Сколько занято сейчас, видно в «Настройки → Система» рядом с кнопкой очистки, а по каждому
файлу — на его странице. Очистка не трогает загруженные программы и модели.

Чтобы черновые дорожки оставались на диске (когда разбираетесь со звуком):
`cache.keep_intermediate: true`.

## Отделение голоса от музыки

По умолчанию стадия выключена: она заметно дольше остальных. Если включить,
оригинальная речь убирается из фонограммы, а музыка и эффекты остаются:

```yaml
separation:
  enabled: true
  model: UVR-MDX-NET-Inst_HQ_3   # загрузится при первом запуске, 67 МБ
```

Замер на тестовом ролике: английская речь подавлена на **40–42 дБ** в речевых
окнах, музыка в паузах потеряла 0.6 дБ. Если Python или модули отсутствуют,
стадия не валит конвейер, а сообщает об этом и уступает место приглушению
оригинала на −18 дБ (`separation.fallback_to_ducking`).

## Голоса

```bash
npx tsx src/cli.ts voices list          # доступные русские голоса
npx tsx src/cli.ts voices list --demo   # синтезировать образец каждого
```

### Два движка синтеза

| | piper | silero |
|---|---|---|
| Русских голосов | 4, из них 1 женский | 29, из них 16 женских |
| Вес | 21 МБ + ~60 МБ на голос | 92 МБ на все голоса сразу |
| Скорость | 0.45 с на реплику | 0.03 с на реплику |
| Что нужно | ничего | Python с `torch` и `soundfile` |
| Лицензия | MIT | CC BY-NC-SA 4.0 (некоммерческая) |

Замеры сделаны на одном и том же эпизоде из 136 реплик: piper озвучил его за минуту,
silero — за двенадцать секунд.

Движок выбирается полем `tts.engine`. Имена голосов у движков свои и не пересекаются
(`ru_RU-irina-medium` у piper, `ru_zhadyra` у silero), поэтому вместе с движком надо
поменять и `tts.default_voice` — иначе настройки не пройдут проверку и скажут об этом.

Дикторы silero — носители языков народов СНГ, читающие по-русски; у части из них слышен
акцент. Зато их хватает, чтобы две героини в одном фильме не звучали одним голосом.

Голос на спикера задаётся в `tts.voice_map`, остальным достаётся `tts.default_voice`.
Для одного видео голоса и громкости удобнее править в интерфейсе, в режиме
«Просмотр и правка» на странице файла: пометки сохраняются в `overrides.json`
рабочего каталога и перекрывают настройки только для этого видео.

### Разные голоса для персонажей

Кто говорит, определяет pyannote (`pyannote/speaker-diarization-community-1`) — локально,
на процессоре, через Python-сайдкар `python/diarize.py`. Спикеры получают имена
`speaker_0`, `speaker_1`… в порядке первого появления; реплика, в которой
говорящий сменился, режется по границе слова. Что нужно один раз:

1. Python 3.10+ и `pip install pyannote.audio` (в интерфейсе — кнопка «Догрузить недостающее»).
2. Бесплатный аккаунт Hugging Face: принять условия на странице модели
   `pyannote/speaker-diarization-community-1`, создать токен
   с правом чтения и вписать его в настройках («Распознавание речи → Токен Hugging Face»)
   или в переменную `HF_TOKEN`. Токен нужен только для загрузки весов (~30 МБ);
   дальше стадия работает офлайн.

Без любого из условий стадия пропускается с объяснением причины, и все реплики
получают `speaker_0`. Результат лежит в `diarization.json` рабочего каталога.

Пол голоса каждого спикера определяется по основному тону записи (`speakers.json`),
и спикер без назначенного голоса получает голос своего пола.

Когда у голосов движка замерен их собственный тон — как у всех дикторов silero, — выбор
идёт дальше пола: героине достаётся голос её высоты, а не «женский вообще». На реальном
эпизоде актрисы звучат на 195 и 176 Гц и получают дикторов на 195 и 177; раньше обе
получали единственный женский голос piper и сливались в одну. Уже занятый голос второй
раз не выдаётся. У голосов piper тон не замерен, и там по-прежнему работает раздача по
кругу. `voice_map` и правки в режиме просмотра важнее автоматики.

Замерить тон своих образцов можно тем же кодом, каким программа меряет актёров:

```bash
npx tsx scripts/voice-pitch.mts <каталог с wav> --match 195,176
```

## Известные ограничения

1. Диаризация не различает голоса, звучащие одновременно: при наложении реплика
   достаётся тому, кто говорит дольше.
2. Экранные надписи и титры не переводятся.
3. При `separation.apply: everywhere` песни теряют вокал вместе с речью. При значении по
   умолчанию — убирать голос только под своей речью — недублированная песня не страдает.
4. Видеокарта используется там, где это окупается, и только там: распознавание через сборку
   whisper.cpp с Vulkan (вдвое быстрее; выбирается вручную, потому что официальных сборок под
   AMD нет), голосовые отпечатки и отделение голоса через DirectML. Синтез, укладка и сведение
   остаются на процессоре. ROCm под Windows не используется — MIOpen не собирает свои ядра,
   это открытый дефект AMD.
5. Оценка длительности реплики — подогнанная модель: постоянная надбавка на реплику плюс
   знаки, делённые на темп, измеренные для конкретного голоса. Это по-прежнему оценка: точную
   укладку обеспечивает стадия S6 темпом, занятой паузой и — в последнюю очередь — сокращением.
6. Языки оригинала кроме английского работают (whisper многоязычный), но часть
   умолчаний рассчитана на латиницу: предел длины перевода, склейка слов для языков
   без пробелов и ширина строки субтитров.

## Безопасность и приватность

Всё, кроме перевода, выполняется локально: аудио и видео не покидают машину. В профиле
`hybrid` на шлюз уходит только текст реплик. Ключи хранятся в `secrets.json` отдельно от
`config.yaml`, в интерфейс передаются только маскированными. Локальный сервер слушает
`127.0.0.1` на случайном порту с одноразовым токеном. Подробности и как сообщить об
уязвимости — в [SECURITY.ru.md](SECURITY.ru.md).
